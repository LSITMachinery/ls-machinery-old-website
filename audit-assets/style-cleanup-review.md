# Style cleanup review — 15 October 2026

## Implemented

- The page loads one local stylesheet, `site.css`, generated by `node scripts/build-styles.cjs`.
- Global design tokens have one source, `styles/tokens.css`. Repeated global token blocks were removed from the base, visual, reference and brand sources.
- Shared section layout, type, spacing and menu container rules now have one owner, `styles/shared.css`.
- The separate annotation correction layer was removed. Static home media, machine menu focus, services menu layout and image-fit rules now live in their component sources.
- The client strip uses the available document content width with container units. It no longer assumes that `100vw` equals the available width after a vertical scrollbar.
- Insights, language and search utility actions have 44px minimum target height. The mobile WhatsApp control also has a 44px target. Footer legal suffixes can remain together using `.company-legal-suffix`.
- Optional production form details and the global catalogue search use the existing page typography and controls.

## Evidence

Compared geometry before and after consolidation for Home, MCD, Solutions and Company at 2504px and 1440px. Main section, heading and image measurements matched. At 390px, all four pages had zero document overflow; a moved mobile current-section spacing rule was restored to its original component.

The desktop Services menu measured 194px high with a scroll height of 194px. All five titles were present, with no image. Insights and language controls measured 44px high.

With a simulated 17px reduction in available document width, the client strip followed the 1423px available width inside a 1440px viewport. It started at zero and ended at 1423px, rather than exceeding the content width by the scrollbar gap.

`node scripts/build-styles.cjs --check` confirms that the compiled file matches the source manifest. This check does not replace the application's browser tests.

## Remaining maintenance work

Some historical component selectors still overlap between the original visual, reference and revision sources. They remain in deterministic build order to preserve the approved composition. This is a consolidated public build with centralized shared rules, not a claim that every legacy component declaration has been rewritten.

Root integration adds new clean route behavior and public controls. Final site regression checks should use the integrated server and routes after those changes finish.
